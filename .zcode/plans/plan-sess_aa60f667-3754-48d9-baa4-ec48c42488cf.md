# 补货监控接入 FlareSolverr 自动突破 Cloudflare 盾

## Context

补货监控 `StockPageAnalyzer.analyzeUrl()` 用 OkHttp 直连商家页，命中 CF 挑战（`isCloudflareChallenge`，StockPageAnalyzer.kt:859）时直接返回 `CHECK_ERROR`「站点触发 Cloudflare 验证」，监控完全失效。目标：接入 FlareSolverr 自动解盾。App 是 Android 客户端，无法本机运行 FlareSolverr（Python+Chrome 服务），因此 App 作为**客户端**调用用户自建实例（常见于 NAS/VPS 局域网 `http://…:8191`）；解盾后的 HTML 直接交给现有 `analyzeHtml()` 分析，不在本机复用 cookie，天然规避 `cf_clearance` 的 UA+IP 绑定问题，且后台 WorkManager 无头轮询同样可用。

FlareSolverr API（已核实）：`POST {base}/v1`，body `{"cmd":"request.get","url":…,"maxTimeout":毫秒}` → `{"status":"ok","solution":{"response":"<html…","url":…,"userAgent":…}}`；失败 `status="error"` + `message`。`{"cmd":"sessions.list"}` 可做廉价健康检查。

## 改动清单

### 1. 领域模型 — `domain/restock/RestockModels.kt`
- `RestockMonitorSettings` 新增 `flareSolverr: FlareSolverrConfig`（`@Serializable`：`enabled=false`、`baseUrl=""`、`maxTimeoutMillis=60_000`）；`normalized()` 中 trim baseUrl、无 scheme 时补 `http://`、clamp 超时 15s–120s。
- `StockAnalysisResult` 新增 `usedFlareSolverr: Boolean = false`。
- 旧 JSON 兼容：仓库 `ignoreUnknownKeys=true` + 默认值，无需迁移。

### 2. 新文件 — `data/restock/FlareSolverrClient.kt`
- 独立 OkHttp client（读超时 = maxTimeout + 15s 余量）+ kotlinx.serialization。
- `suspend requestGet(url, maxTimeoutMillis)`：sealed 结果 `Solved(html, finalUrl, userAgent)` / `Failure(reason, isTransient)`（不可达=transient、解不开=非 transient）。
- `suspend ping()`：`sessions.list` 探活，供 UI「测试连接」。

### 3. 核心接入 — `data/restock/StockPageAnalyzer.kt`
- 新构造参数 `flareSolverrClient: FlareSolverrClient? = null`、`settingsProvider: (suspend () -> RestockMonitorSettings)? = null`（默认 null，现有测试与行为零变化）。
- `analyzeUrl` 中 CF 挑战分支：
  - FS 未启用 → 维持现有错误，errorMessage 追加「可在设置中配置 FlareSolverr 自动突破」；
  - FS 启用 → `requestGet(finalUrl)`；成功 → `analyzeHtml(html=solution.response, finalUrl=solution.url)`，signal 加前缀「CF 盾已突破（FlareSolverr）· …」，`usedFlareSolverr=true`；失败 → 原 CF 错误 + FS 失败原因。
- 主机学习：内存 `ConcurrentHashMap<host,Boolean>`，某 host 命中一次 CF 后续直接走 FS（跳过注定失败、且耗时 ~5s 的直连）。进程级，重启自然重探。

### 4. 装配
- `di/DefaultAppContainer.kt`：`stockPageAnalyzer` 传入 `FlareSolverrClient()` + `settingsProvider = { restockRepository.getSettingsSnapshot() }`。
- `data/restock/RestockCheckWorker.kt` 冷启 standalone fallback 同样接线。

### 5. UI — `ui/restock/RestockMonitorScreen.kt` + `RestockMonitorViewModel.kt`
- 设置底部弹层新增「Cloudflare 盾自动突破」分区：`SettingSwitchRow` 启用开关、baseUrl `OutlinedTextField`、超时档位 FilterChip（30/60/90s，复用 FlowRow 模式）、「测试连接」按钮。
- ViewModel：`setFlareSolverrEnabled/BaseUrl/MaxTimeout`、`testFlareSolverr()`（snackbar 回报）。
- 监控项卡片无需改：evidence 走 `lastErrorMessage ?: lastEvidenceSummary`，signal 前缀自然展示。

### 6. 网络安全 — `AndroidManifest.xml` + 新 `res/xml/network_security_config.xml`
- `<base-config cleartextTrafficPermitted="true"/>` 并在 application 引用。放行局域网 http FlareSolverr；App 本就允许监控任意 http:// 商家页（现状会被系统拦，顺带修正）。

### 7. 测试
- 新 `test/.../restock/FlareSolverrClientTest.kt`（MockWebServer）：ok 解析 / error 消息 / 不可达 transient / ping。
- `StockPageAnalyzerTest.kt` 增补：CF+FS 启用 → 分析 solved HTML 且前缀正确；FS 关闭 → 现有错误含提示；FS 失败 → 错误含原因；同 host 第二次直接走 FS（断言商家 server 仅收到一次请求）。
